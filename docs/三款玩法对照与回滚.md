## 玩法变化

| 游戏 | 原版 | 新版 | 玩家多出的取舍 |
| --- | --- | --- | --- |
| 微光牌局 | 起手换牌后主要依赖正常抽牌；每阵营一种技能 | 每回合一次手牌调度；英雄技能二选一；调整霜息预组 | 花能量改善手牌还是立即建立场面；用技能解场、造物还是补牌 |
| 微光棋阵 | 开战配对；野怪随机发装备；出售棋子才退装备 | 提前看到本轮锁定对手；野怪装备三选一；花金币拆装 | 针对敌人调整站位；选择当前装备还是为后期核心准备；转移装备是否值得牺牲利息 |
| 微光救援 | 进入撤离区自动读秒并引来尸潮 | 自主呼叫；共享战术补给支持诱饵与急救；地图补给箱 | 早叫争取时间还是先布防；补给用于诱敌还是恢复；是否绕路搜集额外补给 |

### 微光牌局

选择一张手牌后可花 **1 能量调度**：放回牌库底，再抽一张，每回合一次。生成牌不能调度，空牌库不能调度。调度不增加手牌数，也不触发连奏、施法和英雄技能次数；返还的牌不公开给对手。

原英雄技能与以下备选技能共用每回合一次的次数，均消耗 2 能量：

| 阵营 | 原技能 | 备选技能 |
| --- | --- | --- |
| 工坊 | 对敌方单位造成 1 伤害 | 拼装零件：召唤 1／1 零件偶 |
| 林地 | 为友方角色恢复 2 生命 | 守望幼苗：召唤 0／2 守护单位 |
| 星塔 | 获得 0 费火花 | 燃灯观星：自身受 2 伤害，抽 1 张；生命不足、满手或空牌库时不能用 |

星塔霜息预组将两张精确投掷、两张断章术，替换为两张流光箭、两张霜环。流光箭帮助周转并启动连奏，霜环应对小单位铺场；因此也放弃了原先的沉默工具。48 张可构筑卡、六套预组、练习／标准／挑战难度保留。默认仍为练习档。

### 微光棋阵

准备阶段确定对手，七名 AI 先完成本轮购买和布阵并锁定，玩家可以查看其实际阵型后操作。野怪轮直接显示怪物。战斗使用准备期的同一配对，避免侦察后临时换敌人。

野怪胜利提供三个不同装备，选择一件后继续；不会重复领取。准备期可花 **1 金币拆下一件装备**，放回背包再分配，棋子仍然保留。AI 根据角色选择和分配装备，八人联赛、共享棋池、升星、羁绊和经济机制继续使用。

### 微光救援

平民到达后先集结，有存活队员在撤离区时可以呼叫；呼叫后开始原有 16／18／20 秒坚守与额外狂暴尸潮。呼叫前总时限和正常刷怪仍在运行；队员离开或敌人压入撤离区会暂停接驳进度。第三关仍须清剿全部敌人。

每关 **2 份共享战术补给**，另有一处需要队员实际接近才能拾取的补给箱。每次能力消耗一份，暂停时也可布置：

- 诱饵：持续 6 秒，吸引 6 格内可到达信标的丧尸，不对它们直接造成伤害。
- 范围急救：2.4 格内、无遮挡的存活队员恢复最多 55 生命；清除尚未转化平民的感染进度，不复活。

投放点须在任意存活队员 4 格内且无遮挡。范围提示、地图标记、物资数量与战场动态共同展示行为结果。

## 对照验证

规则与回放检查 **104 项通过**。桌面 1440×1000、手机 390×844 的实际浏览器操作覆盖新增能力、消耗、结果反馈、装备选择与拆装、查看对手后改站位、三关救援结算。五款游戏的切换、刷新、离线打开与静态子路径回归通过；页面无脚本异常，静态站无后台请求。

历史牌局、旧八人棋阵、三关旧救援的完整回放仍通过原始哈希校验。新版使用 `glimmer-4`／`rescue-4` 回放格式，旧规则单独保留；旧版不承诺读取新规则回放。

原版与试验版浏览器存储隔离，试验版统一使用 `gameplay-v1:` 前缀。浏览器检查向原版写入真实旧局，再在新版操作并回访原版，确认旧局没有被覆盖。隔离也适用于贪吃蛇和乒乓的进度及设置。

### 卡牌：同种子、双方换边

标准规则 AI 对战：六套预组、15 组不同预组配对、6 个种子（71101–71106）、双方换边；每版 180 局，每套预组参与 60 局。原版使用冻结的旧卡表和旧预组，不将新版改牌带入基线。

| 预组 | 原版获胜 / 60 | 新版获胜 / 60 |
| --- | ---: | ---: |
| 工坊零件潮 | 34 | 35 |
| 工坊重装 | 40 | 35 |
| 林地共生 | 33 | 24 |
| 林地萌芽 | 33 | 34 |
| 星塔连奏 | 16 | 22 |
| 星塔霜息 | 23 | 30 |

原版有 1 场平局，新版无平局。平均对局长度由 11.07 增至 11.58 回合（按双方回合数较大者计）。新版出现 132 次调度和 825 次备选技能使用。预组样本胜率分布由 26.7%–66.7% 收窄至 36.7%–58.3%。

这是规则 AI 和固定种子的回归样本，不能等同真人胜率，也不能证明卡组已经平衡。**林地共生下降、星塔连奏仍偏低**，值得后续真人局重点观察；本轮没有为追求样本五五开继续堆数值。

### 棋阵：预告是否可靠

新旧各 8 个种子（72101–72108），运行八人联赛直到玩家淘汰或比赛结算。新版累计 **259 轮**，每轮验证实际敌人与预告一致，没有不匹配；每局出现 7–9 次玩家战利品选择。装备交易与棋池守恒另由规则测试覆盖。

这些对局验证流程可完成，并不证明玩家已能通过站位稳定克制所有阵容。AI 先准备使玩家拥有确定的对手信息，是此次单人体验的主动设计。

### 救援：相同护送路线的三组对照

每关 10 个种子（41003–41012），标准难度；第二关带火力升级，第三关带火力和门障升级。新版等待平民集结再呼叫。三组所有关卡均为 10／10 完成；不操作或只驻守、未护送的方案未完成救援。

| 关卡 | 原版平均结束时间 / 队员剩余总生命 | 新版不用能力 | 新版使用诱饵与急救 |
| --- | --- | --- | --- |
| 1 | 34.30 秒 / 570.4 | 35.98 秒 / 592.8 | 34.01 秒 / 646.4 |
| 2 | 30.67 秒 / 680 | 33.53 秒 / 680 | 33.53 秒 / 680 |
| 3 | 112.40 秒 / 563.4 | 116.00 秒 / 319.4 | 114.48 秒 / 476.4 |

第三关在自主呼叫后，尸潮与清剿时间更紧，合理用补给能降低损耗；第二关当前护送路线的门障已足够有效，能力收益不明显。固定脚本全胜不代表新手全胜，第三关仍应重点观察操作负担。本轮没有把拾取可选补给箱设为通关前提。

汇总数据见 [可复现对照数据](data/gameplay-depth-comparison.json)。运行 `npm run bench:gameplay` 生成逐局结果；`ARENA_RESULTS` 可指定输出目录。浏览器检查分别为 `check:gameplay`、`check:polish`、`check:extraction`。

## 发布与回滚

`npm run deploy:preview` 只添加试验版、原版快照和对照页。发布前必须提交源码并处于试验分支；脚本断言线上根目录 `index.html`、`release.json`、`.nojekyll` 的 Git 内容哈希均未变化。原版快照直接取自旧 Pages 提交，HTML 字节保持一致。普通推送产生新提交，不强制改写发布历史。

**只想继续玩旧版**：打开原站或对照页的原版按钮即可。无需撤销代码，原进度仍在。

**源码切回原版**：先提交当前工作，然后 `git switch main`；如需在基线上继续修改，可用 `git switch -c gameplay/from-baseline baseline/gameplay-2026-11-18`。试验分支保留，不使用丢弃修改的重置方式。

**撤下本次试验页面、恢复整站旧发布**：

```sh
# 先预览，不会改线上：
npm run rollback:pages -- --to 8d58659fd049d6d65be87c5238a0779ee2be3c27

# 确认目标后实际恢复；会撤下本次新增的 preview/、compare/、versions/ 路径：
npm run rollback:pages -- --to 8d58659fd049d6d65be87c5238a0779ee2be3c27 --apply
```

回滚要求目标是当前 Pages 历史中的有效发布，以新提交还原旧树；当前源码分支、标签、浏览器存档仍保留。等待 GitHub Pages 构建完成后检查根目录 `release.json` 的源码版本。以后恢复试验入口，可在干净的试验分支重新执行 `deploy:preview`。

本轮不合并 `main`。三款新机制体验确认后，再决定是否提升为默认版本。
