# 八款游戏逐款打磨

2026 年 11 月 22 日 · 对应[上一轮新玩家评估](八款游戏新玩家试玩与界面精简2026-11-22.md)

本轮按“棋阵 → 漂移 → 救援 → 其余五款”的顺序落实评估建议。重点是让购买、出手、成功和失败在画面中有可辨认的反馈，同时保留上一轮精简后的主界面。

## 逐款变化

| 游戏 | 原来的门槛 | 本轮落实 |
| --- | --- | --- |
| 微光棋阵 | 会买棋，但升星、羁绊和站位的结果不直观。 | 商店显示三合一星级图形；已有同名棋子与下一枚分开表现，连升三星也有提示。羁绊显示进度，拖到棋盘时预览人口与新激活羁绊；满人口会提示需要替换。选中棋子时放大查看，可撤销最近一次布阵。战后高亮“最先倒下”或“主要输出”的实际棋子和位置。 |
| 微光漂移 | 按了漂移，不知道有没有集气成功、什么时候松手。 | 将漂移集气与氮气分开：侧滑痕迹 → 集气条 → 达到真实释放门槛 → 松开小喷。首次成功前强化弯道路面箭头，就绪时按钮和火花变色，小喷有尾焰与速度线。 |
| 微光救援 | 操作简单了，但中后关缺少主动取舍。 | 第 2–6 关加入偏离护送路线的速射补给。接近自动领取，全队强化 25 秒并补满弹药；4 秒预警后引来额外尸群。可以直接护送，也可以冒险绕路，继续使用全队点击、自动射击与接应。 |
| 双蛇争食 | 初次方向与碰撞过程不容易回想。 | 开局短暂显示前进方向；失败后画出实际走过的最后几步，并保留碰撞格和具体死因。保持双蛇争食。 |
| 球台对攻 | 快球、旋球的作用不容易看出来。 | 用实际球路绘制轨迹，快球增加箭头和加粗尾迹，旋球用不同颜色表现弯曲；命中后短暂标出“你／对手 · 快球／旋球”。减少动态效果时缩短尾迹。 |
| 微光牌局 | 常见单位轮廓接近，手机读牌费眼，调度与英雄能力容易混淆。 | 林地和星塔的常见单位使用不同轮廓，召唤物更小，高费核心有独立边框。手机点选手牌后在手牌区就地放大，保持出牌目标可见；调度显示扣费、回库、抽牌，英雄能力显示实际能量消耗。 |
| 微光舞台 | 长音是否仍按住、何时完成不够明确。 | 长音持续亮轨，显示剩余长度进度，完成时出现勾形反馈。修正部分歌曲的背景节拍线误用固定 BPM，改为跟随当前曲目。默认曲开头先出现四个单音，再进入长音。 |
| 微光疾行 | 快速连滑可能被吞成一次，长距离尚未覆盖。 | 连续两次同向换道按顺序执行；加入短输入缓冲，临近落地的跳跃可以接续。补测连续滑动、跳跃接换道和 2450 米六场景循环。 |

棋阵的“撤销”仅恢复最近一次摆放，不退回购买、刷新、升级或出售；通过原有合法布阵动作实现，回放中也保留撤销过程。战后信息是实际发生的事件，不把“第一个倒下”直接断言为整场失败的原因。

牌局没有删减卡牌的实际效果信息。放大预览使用原手牌区域，避免浮层挡住目标；横屏在右侧牌栏放大，竖屏横向展开。

## 救援的两条路线

速射补给缩短开火间隔与换弹时间，不要求玩家选兵、切队或增加技能按钮。黄色闪电箱在领取前标有“速射 25s”和风险符号，领取后在地图入口显示预警，队员身边显示强化状态。第一关仍保留易上手的接应流程。

用同一随机种子 41003、固定升级选择测试两条路线，并校验完整回放。以下是程序执行整队移动指令的结果：

| 关卡 | 直接护送：撤离／损失 | 绕路补给：撤离／损失 | 移动指令：直接 → 绕路 | 结果 |
| --- | --- | --- | --- | --- |
| 2 | 15／0 | 15／0 | 3 → 4 | 均通关 |
| 3 | 20／0 | 20／0 | 4 → 5 | 均通关 |
| 4 | 18／0 | 18／0 | 4 → 5 | 均通关 |
| 5 | 18／0 | 18／0 | 4 → 5 | 均通关 |
| 6 | 18／3 | 19／2 | 7 → 8 | 均通关 |

这些样本证明两条路线均可完成、额外尸潮与奖励确实影响过程；不能据此认定绕路总是更优，也不是不同玩家的胜率统计。第 6 关直接路线峰值同时在场 118 只丧尸，绕路路线 100 只；更强火力会改变存活敌人数，不能单看击杀数判断难度。

新版救援规则为 `rescue-8`。已保存的旧行动继续按原规则进行；在“设置”里选“新版 · 重新部署”，或开始下一关／新关卡后进入新版。主动升级旧行动时保留一份旧存档，关卡进度与升级选择继续保留。历史 1–7 版回放兼容。

## 验收范围与证据

- 204 项规则、回放与输入检查通过，包含新增的升星预览、人口交换、撤销经济约束、漂移门槛、补给只领取一次、旧救援完整回放、连续换道和曲目检查。
- 棋阵使用真实操作生成的购买前存档，在桌面、手机横屏和手机竖屏完成一次三合一，并验证自动布阵及撤销。原有五轮购买、部署、战斗和奖励流程也通过。
- 漂移在浏览器中实际按键触发“集气就绪 → 松手小喷”。两条赛道另由程序车手完成两圈：港湾约 40.57 秒、8 次成功漂移；山岭约 37.88 秒、12 次。两段录像均可重现。程序成绩不代表新人第一圈成绩。
- 救援完成第 2–6 关共十条路线，并测试实际触屏移动领取补给；六关结算、关间升级、解锁和旧版重新部署流程另行检查。
- 牌局完成默认卡组的一局操作流程；320、390 宽度竖屏及 844×390 横屏检查放大牌面、取消和调度。此次不修改卡牌强度或对手难度。
- 舞台六首歌曲的练习／挑战共十二份谱面，逐音符验证命中、长音、双键、完整结算与回放；另在浏览器检查长音发光、完成反馈、双指和暂停恢复。检查的是谱面时序与功能，不能代替试听。
- 疾行实际触控连滑、跳跃接换道；程序沿可行路线跑到 2450 米，再在浏览器完整播放并导出同一录像，覆盖六种场景和回到车站的交界。
- 八款游戏在六种手机尺寸的 48 项布局检查；原生全屏、全屏回退、触摸取消、切换暂停和离线单文件启动均检查。八款的浏览器音频输出信号与设置入口检查通过。

本轮没有开展真人用户研究，也没有实体手机的拇指误触率、扬声器听感、蓝牙延迟和长时发热数据。对手难度没有根据自动化失败分数调整。下一轮仍值得用真实手机重点体验：棋阵点选大小、漂移首次小喷、乒乓技巧收益、舞台音画延迟，以及高速跑酷的障碍判断。

本机证据位于 `output/game-agent-lab/novice-feedback-2026-11-22/`，包含截图、回放、路线对照与浏览器报告。截图和大体积录像不随源码仓库发布。

复现入口：`npm test`、`npm run check:novice`、`npm run check:play-first`、`npm run check:play-access`、`npm run check:rescue-siege`、`npm run check:mobile`。先构建并启动预览；浏览器脚本统一可用 `ARENA_URL` 指向预览地址，`check:novice` 可附游戏名只检查其中一款。
