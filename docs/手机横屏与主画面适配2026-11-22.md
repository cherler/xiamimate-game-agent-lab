# 手机横屏与主画面适配 · 2026-11-22

手机浏览器可以横向呈现游戏。按“宽∶高”计，9∶16 是竖屏，16∶9 是横屏；手机也常见比 9∶16 更长的屏幕。本轮为救援与舞台加入真正的“横屏玩”，并修复救援地图在长竖屏中只占约三成的问题。

## 问题与修改

原救援地图始终保持 3∶2，居中放在很高的容器里；容器铺满页面并不等于地图铺满。顶部还重复放置了开始按钮。原“横屏更好玩”只是一条可关闭的建议，方向锁定失败后没有实际横屏布局。

- **横屏玩**：优先请求浏览器全屏和方向锁定；若屏幕仍是竖向，直接在网页内旋转游戏与操作区域。自然转动手机后取消额外旋转，避免转两次。可点“返回竖屏”。
- **救援竖屏**：整张地图转为纵向视角，六关房间完整显示，文字保持正向，目标与补给标签仍在物体上方／下方。底部保留撤回、驻守、门障。
- **救援横屏**：导航、时间、目标和命令合并到左侧；地图使用屏幕的完整高度，保持等比例，不把圆形角色拉成椭圆。只有一个开始／暂停入口。
- **舞台横屏**：四条音轨铺宽，歌曲与比分压成一行；保留原有竖屏入口。
- **触控**：点击坐标和拖图方向同步转换；舞台画布按旋转前的逻辑尺寸绘制。变换方向时暂停、释放手势、退出救援放大视图，避免误下命令或长按卡住。

本轮沿用原关卡、战斗与谱面规则，保留浏览器进度和旧录像。网页内旋转只启用于本次已验证的救援、舞台，其他游戏继续沿用原来的布局。

## 画面前后对比

占比为**实际地图／音轨画布的面积 ÷ 浏览器视口面积**，不是外框面积。相同手机模拟条件、相同默认关卡，未放大地图；浏览器地址栏属于视口外。

| 游戏与视口 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 救援 390 × 844，长竖屏 | 28.3% | 69.3% |
| 救援 360 × 640，9∶16 | 34.2% | 71.2% |
| 救援 640 × 360，16∶9 | 61.0% | 83.1% |
| 救援 844 × 390，长横屏 | 51.4% | 69.3% |
| 舞台 640 × 360 | 74.0% | 78.9% |
| 舞台 844 × 390 | 76.0% | 80.5% |

在 360 × 640 的竖向浏览器中点“横屏玩”，得到的逻辑布局与 640 × 360 自然横屏相同。页面保持单屏；地图按比例完整显示，所以超长屏幕仍会有少量余白。

## 验证

- `npm test`：207 项通过，新增地图坐标与旋转后拖动方向检查。
- `npm run check:playfield`：两款游戏在 320 × 568、360 × 640、390 × 844 及对应横屏尺寸检查实际画面占比、完整边界、菜单命中、返回竖屏；覆盖六关地图。
- 模拟缺少全屏、全屏被拒绝、方向锁定被拒绝：竖屏／网页横屏／自然横屏点击同一房间，导出的实际命令坐标一致且包含全队；放大后拖图不产生移动命令；切换朝向保留关卡。
- 舞台通过 Chromium 触摸事件发送长按和双指，回放判定一致；旋转暂停后恢复，未留下持续按住的轨道。原生全屏中从其他游戏切入舞台，也可进入网页横屏。
- `npm run check:mobile`：八款游戏共 48 种手机布局通过；原生全屏进出、设置暂停、双指操作、旧赛车录像和离线单文件启动通过。
- `npm run check:rescue-siege`：六关结算、升级、解锁、旧录像、新录像回放通过；108 只丧尸的本机检查正常。
- 静态试玩和离线单文件构建通过；截图检查了地图、标签与控制区。

这些结果来自本机 Chromium 的手机模拟与触摸事件，不是实体 iPhone／Android 验收。原生方向锁定受浏览器支持与全屏条件限制，网页旋转不保证隐藏浏览器地址栏。相关限制见 [MDN：ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。
