## Dota 自走棋界面拆解

参考公开的 PC 版历史实机截图与操作资料：[实机截图出处](https://app2top.com/industry/the-custom-dota-auto-chess-mod-has-returned-a-quarter-of-the-audience-to-dota-2-now-they-will-make-a-mobile-game-out-of-it-138541.html)、[带操作说明的界面资料](https://dota2.17173.com/news/03102019/110342224.shtml)。项目来源可核对 [DOTA AUTO CHESS 创意工坊页面](https://steamcommunity.com/sharedfiles/filedetails/?id=1613886175)。

| 观察到的结构 | 对微光棋阵的设计选择 |
| --- | --- |
| 对局集中在固定屏幕里，棋盘是持续可见的主场景 | 用浏览器可用高度安排整场对局，棋盘随宽高共同适配 |
| 候场棋子在场景中的连续区域，与主战场形成空间关系 | 八个备战位接在棋盘下缘，格宽一致，可直接拖进、拖出棋盘 |
| 五个购买选项以覆盖在场景上的商店展示，可打开或收起 | 上方浮动招募面板，买入、刷新、锁店都在面板内，不增加页面高度 |
| 经济、人口、回合与战斗状态以 HUD 呈现 | 金币、经验、招募入口和开战常驻；商店关闭也能看到资源 |
| 空格用于开合商店 | 支持空格、屏幕按钮和 Escape；输入框和棋子预览弹窗不拦截 |

沿用微光原有绘制与配色，将结构用于浏览器。左侧仍是八名棋手，右侧是羁绊、棋子和装备；主屏较窄时将右栏收进“阵容”，矮屏把操作栏放到棋盘侧边。棋子详情、较长的侧栏和招募面板在必要时内部滚动，主棋盘、备战位和开战操作不随整页滚走。

## 实现后的操作

准备期默认展开招募。购买后点备战棋子会收起招募，可以点格子或拖拽部署；点击“招募棋子”或按空格再次展开。关闭、打开招募不改变棋盘位置。开战自动收起，下一轮再展开。锁店状态保留，刷新仍消耗 2 金。

金币、等级、购买经验和战斗控制常驻。选择己方单位后，可以打开技能／装备详情，或直接移回备战席。野怪战利品三选一和本轮战况在场内浮层显示；选择前不能进入下一轮。结算不额外拉长页面。

## 验证

规则与存档检查共 **107 项通过**。其中新增三个检查覆盖主站复制旧进度、已有新版进度优先、旧存档不被覆盖，以及存储空间不足时仍能读取旧记录。

棋阵专项浏览器操作使用真实合法对局：

- 第一轮购买、棋子技能预览、点选部署、拖拽换位、拖回备战席。
- 商店按钮、空格、Escape；开合不移动棋盘。
- 战斗、野怪战利品、装备与付费拆卸、下一轮自动展开。
- 第八轮侦察、刷新、锁店跨轮；实际对手与预告一致。
- 导出操作后重演校验、刷新接续、旧版完整棋局恢复与再开新版。
- 手机触控落子、侧栏开合、战斗与下一轮；切换到其他游戏恢复正常页面布局。

屏幕覆盖：1920×1080、1440×900、1366×768、1280×640、1024×768、390×844、375×667、320×568，以及 844×390 横屏。验收检查布局视口必须等于指定屏幕，页面无横向或纵向溢出，棋盘、备战席与操作栏边界都在屏内。桌面和手机截图另作人工视觉复核。

五款游戏原有浏览器回归，以及三款新版玩法浏览器检查通过。卡牌、救援的规则未因棋阵布局改动而改变。极窄手机或较矮横屏的棋子仍较小，可点选查看完整详情；详情不会要求整页滚动。

重现：先构建并提供本地页面，再执行：

```sh

python3 -m http.server 4843 --bind 127.0.0.1 --directory site
```

`check:chess-screen` 默认访问 4843，可用 `ARENA_URL` 指定主站根地址；`ARENA_RESULTS` 可指定截图及记录目录。在线主站的三款玩法检查使用 `ARENA_CHANNEL=production`，默认仍兼容上一轮试验路径。

## 合并判断与存档

本轮合并理由：三款新机制增加了可操作的取舍，规则与完整操作流程通过检查，棋阵主要布局问题已解决，主站和源码都有明确回滚点。上一轮卡牌自动对战仍显示部分预组偏弱，救援第三关仍较紧；这些是后续打磨项，不能把合并理解为平衡已经完成。

主站沿用 `gameplay-v1:` 存储前缀。玩过试验版的人直接继续该进度；没有新版记录时，主站首次读取会将原键复制到此前缀，保留原键。正在进行的旧版本对局仍以旧规则结束，新开对局使用新版规则。预览、原版快照路径不进行自动迁移。

发布脚本现在先继承已有 Pages 文件，再更新主站和对照页，逐个验证 `versions/`、`preview/` 文件没有改动。上一轮试验页继续展示旧布局；它与合并后的主站属于同一规则代，使用同一套新版进度。
